# Development constraints

- Keep the public site, `/admin`, content APIs and Better Auth in the root Nuxt app. Install `liti` as a package: verify with packed local artifacts, then commit-specific pkg.pr.new URLs. Stable SDK releases use its existing uppt workflow.
- Void owns D1/R2 connections, local emulation, migrations and Cloudflare deployment. Keep resource configuration in `void.config.ts`, generated schema in `db/schema.ts`, and reviewed SQL in `db/migrations`. Do not reintroduce application database factories, SDK adapters or generated Wrangler configuration patches. Use `db` from `void/db` for application-specific queries.
- `APP_ENV=production` selects `liry24-com`, the existing production D1/R2, the custom domain and its minute Cron. The default/dev target is `liry24-com-dev` with separate D1/R2, no production routes and no Cron. Only `dev` deploys through the Preview GitHub Environment. Do not create branch cleanup jobs or copy production data into dev.
- Commit Void's resolved lockfile after provisioning; verify the resource names/IDs before selecting another environment. Production migration/deployment requires a separate explicit instruction. Ordinary builds and HTTP requests never apply DDL or rebuild indexes; Void applies reviewed SQL during development startup and an explicitly requested deploy.
- A new baseline cannot be applied blindly to an existing database. Back up the source, apply the legacy model/history/i18n transformations on a copy, validate all rows and foreign keys against the new schema, rebuild search, then align the Void/D1 ledgers. Legacy inputs are recoverable from Git at `cb14006d826073855684833058b16505ee3702f9` and the local hash-verified `.data/void-transition` archive. Removing tracked history does not authorize applying the baseline to an existing database. Do not modify old `.data/unified` data. Keep temporary migration tools, exports and operational evidence outside tracked source; do not add migration README/docs.
- Use Vitest. Real AI/model verification requires explicit user approval; use mocked evaluators otherwise. D1/workerd/R2 tests use synthetic bindings with no remote access. Their persistence must be separate from development data. Local development is Void's local D1/R2; no application SQLite driver or migrator may enter Worker bundles.
- Define shared types in shared/types and shared runtime utilities in shared/utils. Keep shared access-control utilities in shared/utils/authAccess.ts. Use Nuxt auto-imports for app/server runtime utils, composables and shared utilities/types; do not add explicit imports from auto-imported directories to make standalone tests work. Test Nuxt-dependent code with `@nuxt/test-utils` runtime mocks or an isolated HTTP fixture, following the existing tests. Keep server helpers in `server/utils`. Config entry points and their helpers also run directly in schema-generation tools without Nuxt's transform, so retain the explicit imports required in that context.
- Keep published, scheduled and current revisions separate. `socials` and `ranks` disable scheduling and history. This app disables draft Blob separation, so unpublished originals remain accessible to anyone who knows their public R2 URL.
- Preserve Better Auth patches that bound rate-limit counters by the actual router's registered template and one unknown-path bucket. Retain route-specific limits; rebase or retire patches when updating packages.
- Authentication secrets and OAuth apps are separate for production and dev. Use direct `/api/auth/callback/<provider>` URLs without an OAuth proxy. Runtime secrets live in Void/Cloudflare bindings, never build output. OG Image requires a separate `NUXT_APP_SECRET` of at least 32 characters for each environment.
- Deployed dev login requires the GitHub identity to have current `admin` permission on `Liry24/liry24.com`; validate the identity and new sessions at login, failing closed on lookup errors. Management APIs use Better Auth sessions and existing role permissions without GitHub lookups. GitHub permission changes apply at the next login; existing session expiry and refresh behavior is unchanged. Local Nuxt development does not call the Preview permission service. Only deploy trusted dev code because deployment uses secrets.
- GitHub Environment `Preview` holds the Cloudflare token, dev auth/OG signing secrets, OAuth credentials and repository permission lookup token. Cloudflare and permission lookup tokens expire on 2026-12-30; replace them before expiry. Never log secret values.
- Renovate uses `renovate/`, targets `dev`, and runs only secretless quality checks. The default `main` needs `renovate.json` with `useBaseBranchConfig: merge` before enabling its App. Do not change Cloudflare Workers Builds settings in this task.
- Generic article slug preparation, proofreading, Markdown protection and publication dates belong to @litijs/blog and @litijs/ai. The app owns game mentions and business validation through authorized model preparation reads. Use liti public entry points; do not query internal content tables or import internal SDK modules.

- Keep the Void native-WASM patches for installed versions until upstream preserves Worker WASM modules when rebundling Nuxt output; the built Worker integration test exercises that exact deployment path.

- Game identity remains immutable in model preparation. Declare game and period uniqueness in model `unique` tuples, enforced by the SDK commit transaction; do not restore application triggers against SDK tables. The fresh liti baseline has not been applied to production data. The user approved backing up and resetting only dev D1 `liry24-com-dev` (`3c7c6179-12d0-4108-9eea-b3e20d394cef`) before this migration; production D1 and R2 are excluded.

- The current liti preview dependencies and the liti/SQLite overrides use the verified `937ee22` commit-specific pkg.pr.new artifacts from merged SDK PR #45. Its AI SDK peer permits compatible 7.0 patches, including the application's 7.0.148. Remove these preview-only overrides when switching to an approved stable release. The migration has passed 149 ordinary tests plus the built Worker, Worker browser and isolated Node browser suites using synthetic data. The dev D1 SQL backup was restored locally and passed integrity and foreign-key checks. Complete the approved dev-only reset before merging this fresh baseline into `dev`, which automatically deploys; retain temporary backup and operational evidence outside tracked source.

- Automatic article slugs use AI as an optional suggestion. When unavailable, blog derives an ASCII kebab-case slug from the title, or a six-character lowercase alphanumeric Nano ID for an empty result. Published and historical URLs are avoided; drafts and scheduled-only entries do not reserve URLs. Manual and established slugs are preserved. Local/browser acceptance uses OPENAI_BASE_URL=http://127.0.0.1:1/v1 to block external AI requests.

- Nuxt owns liti client type generation in .nuxt during prepare/dev/build. Do not track a root liti.generated.ts or require a separate type-generation command. Shared modules and direct Node configuration dependencies retain the ESM imports they need; tests must use the Nuxt environment when exercising auto-imported runtime code.

- Use `@liry24/igdb` for IGDB queries and OAuth; retain app-side response validation, safe errors and local saved-game fallback. Pin its minor version because the package permits breaking changes in minor releases. IGDB credentials remain server-only. Preserve the existing dev runtime IGDB settings when deploying; do not rely on manually configured plain variables surviving a Void deploy.
